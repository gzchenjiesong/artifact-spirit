# 器灵 Artifact Spirit

> **为你的通天灵宝，炼制专属器灵。**
>
> **为 AI Agent 设计的记忆系统：按需回忆、逐级展开，记忆可见、可审、可修，
> 并且作为使用者的「认知资产」能跨 Agent 平台迁移。**
>
> 一句话分野：向量库给你**找得到**；器灵给你**记得住、说得清、带得走**。

---

## 为什么需要它

**Agent 平台是工具；你和它之间攒下的那些记忆，才是属于你的认知资产。**
而今天，这两样被绑在了一起。

在一个平台上用上一两年，你的偏好、习惯、项目背景会在它那里攒成一份
**关于你的资产**。直到你想换平台——新的更强，或者旧的已经不再维护。
这时你会发现：

- **换个平台，一切归零。** 新平台上的助手像第一次见你。这不是它记性差，
  而是那份资产**从一开始就不在你手上**。
- **搬过去的又是个黑盒。** 你只能把旧记录倒过去，可它到底记住了什么，
  你看不见——记错一条，既发现不了也改不掉。
- **根子在于资产被平台绑住。** 能不能带走、带走成什么形状，**全看平台的脸色**。
  于是"换个平台"不再是对等的选择，而是一次**不得不接受的损失**。

器灵只做一件事：**让这份认知资产能跨 Agent 平台迁移**——
不绑任何平台，导出成开放、人类可读的格式。换到哪里，它都还是你的。

> **一条承诺**：器灵**不会**因为你很久没想起某件事就删掉它。
> 长期未用只会让它降权、退出自动召回，需要时仍可搜回。

## 它守什么

**三条承重墙**——砍掉任何一条，器灵就不再是器灵：

| 承重墙 | 没有它会怎样 |
|---|---|
| **分级加载**（L0 → L1 → L2） | 退化成又一个全量检索 |
| **可审查、可复盘** | 退化成又一个黑盒 |
| **记忆可迁移** | 退化成又一个锁定 |

**六条设计原则**：

| # | 原则 | 违反的后果 |
|---|---|---|
| 1 | **记忆是资产，工具只是载体** | 使用者换个工具就得从零开始 |
| 2 | **按需回忆，而非全量灌输** | 上下文被塞满，注意力被稀释 |
| 3 | **可见即可信，不可审即不可用** | 记忆污染与自相矛盾永远发现不了 |
| 4 | **结构化是真相，文本是投影** | 出现两套事实，无从对账 |
| 5 | **记忆系统绝不阻断宿主** | 记忆出问题让整个助手不可用 |
| 6 | **边界先于实现，分层可独立验收** | 改一处崩一片，无法逐层推进 |

## 核心目标

**首要——项目的存在理由**

| | 目标 | 说明 |
|---|---|---|
| **P1** | 分级记忆 | 先给模糊印象，需要时才逐级展开细节 |
| **P2** | 可查看、可审查、可跟踪 | 逐条看到记住了什么、从哪来、何时改的 |
| **P3** | 记忆资产可迁移 | 导出为开放、人类可读、不依赖运行时的档案 |

**追加——补全通用方案的弱点**

| | 目标 | 说明 |
|---|---|---|
| **A1** | 会记 | 而不只是"能用" |
| **A2** | 有取舍 | 显著性过滤，不是照单全收 |
| **A3** | 会沉淀 | 从碎片里巩固出更稳定的知识 |
| **A4** | 有自我 | 有一层属于使用者自己的人格内核 |
| **A5** | 可逐层落地 | 每一层都能独立验收 |

## 功能特色

| | 特色 | 说明 |
|---|---|---|
| **核心** | 分级加载 | 先给一句话印象，需要时才逐级展开到原文 |
| | 可审查、可复盘 | 逐条看到记住了什么、从哪来、何时改的，并可当场修正 |
| | 记忆可迁移 | 导出为开放、人类可读的档案，不依赖器灵运行时 |
| **增强** | 五类记忆 + 人格内核 | 情景 / 语义 / 程序性 / 核心记忆分工，另有一层"元认知"负责调度 |
| | 会取舍 | 显著性过滤——不值得记的，不占地方 |
| | 会沉淀 | 巩固提升——碎片沉淀为更稳定的知识 |
| | 会联想 | 扩散激活——想起一条，能带出相关的一串 |
| | 会进化 | 新信息到来时，反过来完善旧记忆的摘要 |
| **工程** | 零部署、零 AGPL | 单文件 SQLite，无外部服务，无图数据库 |
| | 可插拔 | 多后端、多模型，协议与实现分离 |
| | 边界可固化 | 分层规则 R1–R10 由测试强制，改一层不会崩另一层 |

## 快速开始

```bash
pip install -e .

# 1) 生成配置模板
aspirit init

# 2) 把密钥放进环境变量（**密钥永不写入配置文件**）
export ARTIFACT_SPIRIT_API_KEY="sk-..."

# 3) 体检：配置 / 数据库 / 模型可达性
aspirit doctor

# 4) 看状态：层计数 / 健康度 / 生效模型链 / 降级告警
aspirit status

# 5) 逐条审查器灵记住了什么
aspirit review

# 6) 导出人类可读档案（纯文本即可阅读）
aspirit export ~/my-memories.md
```

未配置任何模型也能启动：器灵会依次尝试**宿主配置**与**通用环境变量**；
全都取不到时，记忆照存原文，只是不做结构化提取。

## 五类记忆

器灵把记忆分成五类，另加一层负责调度。名字取自"为通天灵宝炼制专属器灵"的意象；
**文档与代码一律使用通用术语**，修仙名只是别名：

| 修仙名 | 通用术语 | 含义 |
|---|---|---|
| 灵犀 | 感觉记忆 · Sensory | 门口，判断值不值得记 |
| 灵台 | 工作记忆 · Working | 会话内的活跃内容（4±1） |
| 灵识 | 情景记忆 · Episodic | 当时发生了什么 |
| 灵纹 | 语义记忆 · Semantic | 一般来说是什么 |
| 灵髓 | 程序性记忆 · Procedural | 可复用的技能与轨迹 |
| 灵核 | 核心记忆 · Core | 人格与身份 |
| 元灵 | 元认知 · Metacognition | 巩固、衰减、激活的调度 |

## 架构

```
AL1 适配层   →  宿主契约、工具、CLI            （只做翻译，不做决策）
AL2 核心层   →  五类记忆、元认知、提取器       （纯逻辑，零 I/O）
AL3 存储层   →  SQLite + sqlite-vec           （真相源）
AL4 模型层   →  LLM / Embedding 协议与 fallback
AL5 辅助机制 →  线程、配置、可观测、合规
```

依赖方向单一：`Adapter → Core → Port ← Backend`。
`core/` 不认识任何具体后端与模型——这是它可被独立测试、可被替换的原因。

## 与相邻方案的分野

| 方案 | 它给什么 | 器灵多了什么 |
|---|---|---|
| 向量数据库 | 找得到 | 记得住：分层、巩固、取舍 |
| 宿主内置记忆 | 能用 | 说得清：可审查、可溯源、可干预 |
| 托管记忆服务 | 开箱即用 | 带得走：开放格式、不依赖运行时 |
| 通用上下文数据库 | 通用存储 | 借鉴脑科学机制（但每条都要过"有效"这一关） |

**明确不做**：不做 Agent / harness · 不做向量数据库 · 不做通用知识管理 ·
不追 benchmark 排名 · 本版不做 SaaS · 不替代宿主内置记忆。

## 许可与合规

**MIT**。默认栈不引入任何 AGPL 依赖：

- 不引入传染性许可（AGPL / SSPL）或许可不明的依赖（INV-10，由仓库内的合规检查强制）
- 不引入图数据库——语义图用 SQLite 自建
- 不引入 `openai` SDK——用 `httpx` 直连 OpenAI 兼容协议
