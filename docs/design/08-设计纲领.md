# Part A · 项目纲领（读者向）

## 1. 一句话定位

> **器灵是为 AI Agent 设计的记忆系统：它按需回忆、逐级展开，让记忆可见、可审、可修，
> 并且让作为「认知资产」的记忆能跨 Agent 平台迁移。**

面向 Hermes Agent 的 Memory Provider 插件；零部署、MIT 协议、纯文本。

### 1.1 所以呢？（用户视角总括）

如果你用一个 AI 助手超过一年，大概已经体会过三件事：

| 你的体感 | 本质问题 |
|---|---|
| **它每次都像第一次见你** | 你说过的偏好、正在做的项目、上次定下的方案——**换个 Agent 平台，全部归零** |
| **就算它记住了点什么，你也不知道它记住了什么** | 记错的地方改不了，记偏的地方你不知情 |
| **你不敢把重要的东西托付给它** | 因为换一个平台，这份**认知资产**就没了 |

**这三条不是并列的，是一条链**：认知资产被平台绑住（第三条）→ 于是换个平台就归零（第一条）
→ 于是你只能把旧记录倒过去，而倒过去的那个东西**是个黑盒**（第二条）。

根子在第三条——**Agent 平台只是工具，而你和它之间攒下的记忆才是属于你的认知资产**（V3）。
器灵要做的只有一件事：**让这份认知资产能跨 Agent 平台迁移**。
所以下面三条对策也不是并列的：第三条（记忆属于你自己）是另外两条的前提。

**器灵针对的就是这三件事**：

- **按需回忆** —— 先给模糊印象，需要时才逐级展开细节。不把几十年的事一次性塞进上下文。
- **记忆可见、可审、可改** —— 你能一条条看到它记住了什么、从哪来、什么时候改的，并且当场修正。
- **记忆属于你自己** —— 完整导出为开放可读的格式。换工具、换平台，记忆照样带走。

**还有一条承诺**：

> 系统**不会**因为你很久没想起某件事就删掉它。长期未用只会让它"**降权**"（可逆）；真正销毁数据需要你明确要求——而你的每一次要求都会被记录在案。

### 1.2 一句话分野

> 向量库给你**找得到**；器灵给你**记得住、说得清、带得走**。

## 2. 设计原则（6 条）

四条分组。每条都给出**违反的后果**——没有代价的原则不是原则，只是愿望。

### 组一 · 价值归属

| # | 原则 | 违反的后果 |
|---|---|---|
| **P1** | **记忆是使用者跨越工具的长期资产**——要能带走**内容、语义、策略**三层 | 退化为又一个宿主插件，天花板锁死在宿主上 |

> **"三层"的含义**：不只是把原文搬走——还要带走**语义结构**（实体与关联）和**策略**（哪些重要、什么时候该想起）。只带走纯文本，等于带走了尸体。

### 组二 · 架构边界

| # | 原则 | 违反的后果 |
|---|---|---|
| **P2** | **认知决策不外包**——存储与检索可以交给后端，**巩固 / 升格 / 去重必须自己做** | 退化为存储的薄封装，放弃唯一的算法差异化 |

### 组三 · 认知机制

| # | 原则 | 违反的后果 |
|---|---|---|
| **P3** | **按需回忆，而非全量灌输**——上下文是最稀缺的资源（即**注意力预算**，依据见 [DES-RES-003 §2](./10-神经科学依据与机制映射.md)） | 把全部相关记忆塞进 prompt：注意力被稀释、成本失控、噪音淹没信号 |
| **P4** | **机制既要讲得通、又要测得出**——认知科学只提供假设，不提供正确性 | 变成伪脑科学包装：机制堆砌、无法验证、越加越吵 |

> **P4 的完整含义**（详见 [DES-RES-002 §5](./09-机制决策依据研究.md)）：
> 一个机制要进主线，必须过三关——**① 合理性**（在信息论/认知层面讲得通，且论证不依赖"因为人脑这样"）→ **② 有效性**（在 Agent 场景实测有增益）→ **③ 正交性**（不与已有机制抢同一份收益）。
> **禁止以"人脑如此"作为立项理由。** 神经科学只是假设来源之一，真正的裁判是 Agent 在真实任务上的表现。
> **素材与判据**：脑科学究竟提供了哪些**可用的约束与量**（容量 4±1、重要性与频率独立、衰减长尾、共现结构）、每条机制对应什么 Agent 侧判据与放弃条件，见 [DES-RES-003](./10-神经科学依据与机制映射.md)。
> **表述纪律**：脑科学一律表述为"**借鉴脑科学**"（来源），**禁用"类脑 / 仿脑 / 像人一样"**，也**禁止拿"像不像脑"当论证或卖点**——见 [TERM-000 §10](./06-术语与命名规范.md)。

### 组四 · 可信与治理

| # | 原则 | 违反的后果 |
|---|---|---|
| **P5** | **可见即可信**：可读 → 可审 → 可干预 | 黑盒记忆：能召回却解释不了，出错无法归因，用户建立不起信任 |
| **P6** | **降级必须显式，绝不静默丢数据** | 用户以为迁过来了，实际丢了，且**无从发现** |

## 3. 核心目标（6 个）

| # | 目标 | 达成标志 | 档 |
|---|---|---|---|
| **G1** | **长期资产化** | 换工具 / 换宿主后，记忆完整、行为一致 | 首要 |
| **G2** | **自由迁移** | 记忆包往返**幂等**；目标环境能力不足时给出**降级报告** | 首要 |
| **G3** | **可治理** | 用户能回答三个问题："它记住了什么 / 为什么这么判断 / 怎么改" | 首要 |
| **G4** | **注意力高效** | 默认只注入摘要；Agent 按需逐级展开细节 | 首要 |
| **G5** | **认知演化** | 情景能升格为语义；矛盾的错误记忆能被失效替换 | 追加 |
| **G6** | **可验证** 🆕 | 有**自建评测集**，能证明机制优于扁平基线 | 追加 |

### 3.1 目标的分档来源

| 档 | 来源 | 含义 |
|---|---|---|
| **首要** | **原始动因** | 当初选型时的核心理由；**决定这个项目为什么存在** |
| **追加** | 补全前者的不足 | 借鉴脑科学机制的用武之地；**决定它比一个分级存储好在哪**（证据与判据见 [DES-RES-003](./10-神经科学依据与机制映射.md)） |

**冲突时首要优先。**

> **G6 是本次评审新增的**（见 [DES-RES-002](./09-机制决策依据研究.md) §5、§7.2）。理由：G1–G4 都可以直接验收，唯独"借鉴脑科学机制是否真的更好"此前**只论证了'有根据'，没论证'有效果'**。补上 G6，纲领才闭环：
> **有根据（P4 第一关）→ 有效果（G6）→ 才进主线。**

## 4. 功能特色

按**承重等级**排列——这不是功能清单，是"项目在保护什么"。

### 4.1 承重墙（砍掉就没了这个项目）

> **📄 README 版（简要）**——让读者一眼看到"项目在保护什么"：
>
> **这个项目在保护什么？** 三条承重墙——砍掉任何一条，器灵就不再是器灵：
> 1. **分级加载** —— 先给印象，需要时才展开（没有它 = 又一个全量检索）
> 2. **可审查可复盘** —— 逐条可见、可溯源、可修正（没有它 = 又一个黑盒）
> 3. **记忆可迁移** —— 开放格式，换工具不归零（没有它 = 又一个锁定）

**完整版**（含撑起的目标）：

| 特色 | 说明 | 撑起 |
|---|---|---|
| **分级加载（渐进披露）** | 先给模糊印象，需要时才逐级展开细节 | 目标 G4 |
| **可审查可复盘** | 逐条看到记住了什么、从哪来、何时改的；可当场修正 | 目标 G3 |
| **记忆可迁移** | 记忆包 + 内容寻址指纹 + 能力协商与降级报告 | 目标 G1 / G2 |

> **三条承重结论**：
> - **分级加载 + 可审查 = "可治理"的全部** —— 没有它们，P5 无法落地
> - **巩固升格 + 衰减排序 = "认知机制"的全部** —— 这是我们区别于所有现成方案的核心
> - **记忆包 + 内容寻址 = "可迁移"的全部** —— 项目的立身之本

### 4.2 认知机制（核心差异化）

| 特色 | 承重等级 |
|---|---|
| **巩固与升格**（情景 → 语义 → 程序） | 承重墙 |
| **衰减排序**（时间 + 重要度**双因子**；**只影响排序，不触发删除**） | 关键支撑 |
| **多路检索融合**（语义 + BM25 + 实体 + 重要度 + 时间 + 关联） | 关键支撑 |
| **分层抽象**（五类记忆 + L0/L1/L2 详略级） | 关键支撑 |
| **扩散激活**（共现关联，Hebbian） | 加分项 |
| **模式分离 / 交错重放 / 元记忆** | ⚠️ **实验特性，默认关闭** |

> **"不删除"是一条明确承诺**（D-16 / D-17 / D-23）：
> 系统**不会**因为"你很久没想起它"而删掉你的记忆。长期未用只会让它**降级为只留摘要**（可逆），需要时仍可搜回。
> 删除只在**记忆优化任务**（发现错误 / 冲突 / 图结构上不可达）或**你明确要求**时发生。
> 而且**默认可恢复**——每次删除都留下完整快照，你可以把它找回来；只有合规性的删除才是真的不可逆。
> 我们把删除当作**治理动作**，而不是**认知机制**——这两件事性质完全不同。

> **"实验特性"的含义**（P4 的直接应用）：这些机制在认知科学上有名有据，但在 Agent 场景的**增益尚未被实测证明**。它们默认关闭，只在实验开关下试跑，**不得进入主线**。

### 4.3 工程特色

| 特色 | 说明 |
|---|---|
| **零部署、零 AGPL** | SQLite + sqlite-vec，单文件，全 MIT 友好 |
| **后端 / 模型可插拔** | 换存储或换模型厂商，代码零改动 |
| **契约测试 + 逐层可验收** | 五层各有 fake 替身与验收清单 |
| **绝不阻断宿主** | 全故障点降级矩阵；召回超时有保底返回 |

## 6. 明确不做（非目标）

| 非目标 | 理由 |
|---|---|
| 不做 Agent / harness 本体 | 我们是插件，不跟宿主竞争 |
| 不做向量数据库 | 那是组件，不是产品定位 |
| 不做通用知识管理 | 聚焦个人长期记忆 |
| **不做私有记忆格式** | 与 G1/G2 直接冲突——不能自己成为新的锁定方 |
| 不替代宿主内置记忆 | 二者并存，不是替代关系 |
| v0.x 不做 SaaS / 多租户 | 聚焦单用户 |
| **不追公开 benchmark 排名** | 见下注 |
| 不做限流器 / 队列持久化 / 多跳扩散 | 明确的过度设计 |

> **关于"不追 benchmark"与 G6 的关系（不冲突）**：
> **G6 要求的是"自建评测集证明机制有效"**，属于**工程可验证性**；**不追排名**是指不为了刷公开榜单而优化。前者是**对内自证**，后者是**对外攀比**。做自己的 A/B 评测，不等于去争 LoCoMo 榜首。

# Part B · 工程自我约束（内部向）

> 以下 7 条是我们的**落地自律**。它们不进 README——读者不需要知道我们怎么管自己，只需要知道项目解决了什么问题。

| # | 约束 | 违反的后果 |
|---|---|---|
| **E1** | **结构化是真相，文本是投影**——单向映射，永不双向同步 | 复刻强制 markdown 的弊端：高频写文本、双向同步、格式破坏 |
| **E2** | **边界先于实现**——依赖单向（R1–R10）+ 每层可独立验收 + CI 固化 | 先写代码再重构分层，在 vibe coding 下必然长成泥球 |
| **E3** | **借范式，不引依赖**——只抄设计不抄代码；拒绝图数据库与官方 SDK | 为省事引入 AGPL 或重型服务，把项目未来锁死（协议不可逆） |
| **E4** | **显式分期，不留隐性遗漏**——没做的事必须写清"为什么没做" | 设计承诺静默落空（本项目真实发生过：实体匹配 / A-MEM / 双时态三项） |
| **E5** | **真相唯一，派生可重建**——派生字段可由真相重算 | 多处维护同一事实 → 必然漂移，且无法判断哪份是对的 |
| **E6** | **绝不阻断宿主**——非阻塞 + 超时护栏 + 保底返回 | 记忆检索超时拖死对话，用户第一时间卸载 |
| **E7** | **用例是设计的断言，不是通过率的来源**——代码与用例冲突时，**先判用例是否忠于设计**；用例错就改用例，**永不改代码去迁就一个错的用例** | 门禁从"设计的守卫"退化成"现有行为的快照"：设计改了用例不改，用例过时了还留着，需求演进被旧用例挡住，最后只能改设计去凑用例 |

### E7 的完整含义（裁决顺序与禁止项）

**E7 不是"测试要写对"这种空话，它规定的是一套可执行的裁决程序。**

**① 裁判顺序**（冲突时按此定谁对谁错）：

```
功能设计意图（DES-000 的目标 / 原则 / 不变量）
      ↓
LLD 契约条款
      ↓
编码任务书的验收项
      ↓
用例
      ↓
实现
```

**上游是下游的裁判**——冲突时先定位"是哪一层先偏离的"，再决定改哪一边。

**② 三类处置**（不许含糊）：

| 冲突形态 | 谁错 | 改哪边 |
|---|---|---|
| 用例与条款/设计不符 | **用例**过时或被改写 | **改用例** |
| 条款文字与设计意图不符 | **文档**过时 | **改文档**（并同步该条款的用例） |
| 实现未兑现条款 | **实现**缺失 | **改实现** |

**③ 两条禁止**：

- **禁止为了让门禁变绿而降低断言强度**——把断言改成恒真，等于把守卫换成布景（本项目实测存在：`assert resp.ok in (True, False)`）。
- **禁止改实现去迎合一个与设计不符的用例**——那等于让**过时的用例决定产品走向**，比测试不过更糟。

**④ 过时用例与过时代码同规格处置**：显式裁决、留痕、改写或删除，**不允许静静地留着通过**。

**⑤ 可执行化**（E7 不能只写在文档里，否则它就违反 E7 自己）：

- `tests/acceptance_matrix.py`：**验收项 ⇄ 设计条款 ⇄ 用例**的追溯矩阵
- `tests/test_acceptance_matrix.py`：机械校验——条款编号存在、用例存在、缺口与过时项必须带裁决编号且能在评审日志里找到

> **与 E4 的关系**：E4 管"**没做的事**要说清"（功能承诺不得静默落空）；E7 管"**做过的验证**要说清、要跟着设计走"。两者共同堵住"静默"这个失效模式，只是对象不同。

> 物理删除**只有两个入口**：① **记忆冲突被修正**时的"优化性遗忘" ② **用户显式要求**。

### 7.3 已裁决（2026-09-16）

| # | 议题 | 结论 |
|---|---|---|
| Q6 | **用例与设计的同步纪律**——设计改了用例不跟、用例过时了还留着，编码端两头堵 | ✅ **已定**：升为工程约束 **E7**。裁判顺序＝**功能设计意图 > LLD 条款 > 验收项 > 用例 > 实现**；**用例错就先改用例，永不改代码去迁就错的用例**；禁止为让门禁变绿而降低断言强度；过时用例与过时代码同规格处置（显式裁决 + 留痕 + 改写或删除） |

**Q6 的完整结论**：

> 一切测试用例的**合理、正确，远比通过性更重要**。
>
> 代码与用例不匹配时，**第一件事是问"用例是否符合设计文档要求、是否符合功能设计结果"**，
> 而不是一味追求用例通过；**如果用例不对，就先改用例，而不是改代码去匹配用例**。

**Q6 的由来**：第四轮逐层复核（[DES-REV-004](./07-设计评审.md)）在 AL1 层实测到三类同源现象——
**验收原文被用例悄悄改写成"能过的形式"**、**断言弱到无法失败**、**条款过时但用例还钉着它**。
三者的共同点是：**门禁看起来在工作，实际守卫的是一份已经过期的设计**。

> **v1.1 → v1.2 的唯一变动**：Part B 增补 **E7**（Q6）。Q1–Q5 结论未变，E1–E6 未变。
