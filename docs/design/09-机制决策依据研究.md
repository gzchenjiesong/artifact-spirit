# 器灵 / Artifact Spirit — 记忆机制的决策依据研究

> 文档编号：**DES-RES-002**
> 日期：2026-09-14
> 触发：纲领评审中，用户对两条机制性原则提出根本性质疑
> 结论摘要：**P5 应修正为「注意力分配是一等公民」；P4 应补上「有效性」这一环——神经科学只提供假设，不提供正确性。**

---

## 0. 待论证的两个问题

### 0.1 P4：机制凭什么进设计？

原表述：*"机制必须有科学根据——只借计算原理不借名词"*

**质疑**：我们把"借鉴脑科学"当成卖点，但**人脑会这么做**不等于**Agent 该这么做**。我们是设计一个 Agent 的记忆，不是做仿生学。**能实打实提升 Agent 能力才是目标。**

### 0.2 P5：遗忘凭什么是一等公民？

原表述：*"遗忘是一等公民"*

**质疑（三层，逐层递进）**：

1. **人脑的遗忘是生物限制**（容量、代谢成本），不一定是 Agent 必须
2. **L0/L1/L2 多层抽象本身已经是遗忘**——隐去细节、保留要点，而且这**提升思考效率**，本身就是遗忘机制的体现
3. **按访问频率删除记忆，不一定适合 Agent**

> 用户判断：这两块对系统最终运行质量影响巨大，**需慎重，需深入调查**。

---

## 1. 问题的实质：我们一直在做错误的类比

现有设计里，"借鉴脑科学"的论证链条是这样的：

```
人脑有 X 机制（有神经科学依据）
        ↓  ← 这一步从未被论证
Agent 也该有 X 机制
```

**中间那一步是跳跃的。** 它默认了"生物的机制 = Agent 的最优解"，而这个默认恰恰不成立——因为**两者的约束条件根本不同**。

---

## 2. 生物记忆 vs Agent 记忆：约束根本不同

| 维度 | 生物大脑 | Agent 记忆系统 | 差异的含义 |
|---|---|---|---|
| **存储容量** | 有限，有代谢成本 | **近乎免费**（几十万条在 SQLite 里是小事） | 生物必须删；Agent 不必 |
| **检索代价** | 随干扰上升，有激活阈值 | 有索引 ≈ 常数级 | 生物检索会"找不到"；Agent 不会 |
| **真正的稀缺资源** | 存储 + 检索带宽 | **上下文窗口 / 注意力预算** | **稀缺的地方不一样** |
| **遗忘的成因** | **被动**（衰减、干扰、容量上限） | **无被动成因**——不删就永远在 | Agent 的遗忘必须**主动设计** |
| **目标函数** | 生存与适应 | **任务表现** | 评价标准不同 |

### 2.1 核心洞察

> **生物遗忘的根本原因是资源约束。Agent 没有这个约束——所以"因为人脑会忘，所以 Agent 也该忘"是错误类比。**
>
> **但 Agent 有另一个稀缺资源：上下文窗口。**
>
> 因此：**Agent 需要的不是"遗忘记忆"，而是"遗忘它在注意力里的位置"。**

这一句是整个研究的支点。它把"遗忘"从**数据销毁**重新定位为**注意力分配**。

> **配套文档**：[DES-RES-003](./10-神经科学依据与机制映射.md) 把本节结论展开为"可用的约束与量"的逐条映射——注意与工作记忆容量 4±1（Cowan 2001）、重要性与频率的独立性、衰减的长尾形状（Wixted & Ebbesen 1991）、共现的统计结构——并给出每条机制对应的 **Agent 侧可测判据与放弃条件**。

---

## 3. "遗忘"到底要解决什么？—— 七类诉求拆解

人们说"需要遗忘"时，其实想要的是不同东西。逐条拆：

| # | 表面诉求 | 真实诉求 | 必须物理删除吗？ |
|---|---|---|---|
| 1 | 记忆太多，检索噪音大 | **排序质量** | ❌ 提高排序区分度即可 |
| 2 | 上下文塞不下 | **注意力预算** | ❌ 分级加载 + 摘要 |
| 3 | 信息过时了 | **时效性** | ❌ 时态标记 + 降权 |
| 4 | 信息自相矛盾 | **一致性** | ⚠️ 标记失效优先；物理删除非必需 |
| 5 | 存储成本 | — | ❌ **不是问题**（见 §2） |
| 6 | 隐私 / 合规"被遗忘权" | **真删除** | ✅ **必须** |
| 7 | 用户明确说"忘掉这个" | **真删除** | ✅ **必须** |

### 3.1 结论

**七类诉求里只有两类（6、7）真正需要物理删除。**

其余五类都能用**排序 + 抽象 + 时态**解决——而且解决得更好，因为它们**可逆**。

> 这恰好把用户的直觉严密化了：**L0/L1/L2 分层抽象，就是"注意力层面的遗忘"**——保留要点、淡出细节、随时可回溯。它比删数据更优雅，且不会造成不可逆损失。

## 4. 重新定位"衰减"：从删除触发器 → 排序信号

### 4.1 现有设计的问题

当前 `[LLD-AL2 §5 M3](./layers/AL2-核心层详细设计.md)` 的设计是：

```
strength(t) 按时间衰减
  └─▶ strength < θ_forget → 进入候选遗忘集
        └─▶ 三级处置：dormant / archive / forget
```

**三个具体问题**：

**问题一：按访问频率衰减，会优先杀掉"低频但关键"的记忆**

反例（全部真实且致命）：

| 记忆 | 调用频率 | 一旦缺失的后果 |
|---|---|---|
| 身份证号 / 血型 / 过敏史 | 极低（一年可能一次） | **不可接受** |
| 家庭住址 / 紧急联系人 | 极低 | **不可接受** |
| 某个项目的关键决策背景 | 低 | 需要时回忆不起来 |

**低频 = 不常想起 ≠ 无价值。** 用频率做删除依据，等于系统性地淘汰最不可替代的那部分记忆。

**问题二：这个设计与记忆研究的结论相悖**

记忆研究里，**重要性（importance）与频率（frequency）是两个独立维度**。情绪唤醒度高、对个体重要的记忆，巩固更强、衰减更慢（这就是"闪光灯记忆"现象的基础）。

**纯按访问频率衰减 = 一个既与记忆研究结论相悖、也不适合 Agent 的设计。**

> 注意这里的引用方式是**记忆研究的可检验结论**（两个维度的独立性 + 衰减速率差异），而不是"人脑这么做所以我们也这么做"。**"像不像脑"从来不是判据，"在 Agent 上是否有效"才是。**

**问题三：`archive` 级（丢弃 L2 详情）在存储免费的前提下没有道理**

丢掉细节换来的是"省了几乎为零的存储"，代价是**不可逆的信息损失**。

### 4.2 重新定位（建议）

```
strength 的用途重新定义为：召回排序的权重，而非删除的触发器
```

| 要素 | 新定位 | 理由 |
|---|---|---|
| **时间衰减** | ✅ 保留为**排序信号** | 近期事件通常更相关——这是**统计规律**，不需要生物学论证 |
| **访问回升**（间隔重复） | ✅ 保留为**排序信号** | 被反复需要的东西，更可能再次被需要 |
| **重要度 / 置信度** | 🆕 **升为独立因子**，与频率解耦 | 修正"问题一/二" |
| **衰减触发删除** | ❌ **移除** | 改由白名单触发物理删除 |

### 4.3 物理删除收窄为白名单

| 触发条件 | 说明 |
|---|---|
| **用户显式要求** | `aspirit forget <id>` / `spirit_forget` |
| **合规要求** | 隐私数据、被遗忘权（GDPR） |
| **明确的矛盾失效** | `INVALIDATE`（且优先考虑"标记失效 + 保留可溯"而非物理删除） |

**不在白名单内的一律不删除。**

### 4.4 三级遗忘 → 两级

| 现状 | 建议 | 理由 |
|---|---|---|
| `active` | `active` | — |
| `dormant`（退出自动召回，可显式搜回） | `dormant` ✅ 保留 | 这就是"注意力层面的遗忘"，可逆且有效 |
| `archive`（丢 L2 详情） | ❌ **取消** | 存储免费；讨论"细节多少"属于**摘要层（L0/L1/L2）**的事，不属于**删除层** |
| `forget`（物理删除） | `forgotten` ⚠️ 保留但**仅白名单触发** | 治理动作，非认知机制 |

> **层级归位**：`dormant` 管"在不在注意力里"；L0/L1/L2 管"看到多少细节"；`forgotten` 管"数据还在不在"。**三件事不该混在一个机制里。**

## 5. 机制准入标准（对 P4 的回应）

用户的判断是对的：**神经科学是假设的来源，不是正确性的证明。**

但也不能走向另一极端（"只要有效，机理随便编"）——因为无法证伪的机制会无限堆积。**需要可操作的准入标准。**

### 5.1 三关准入

| 关 | 问题 | 判据 | 不过关怎么办 |
|---|---|---|---|
| **① 合理性** | 在**信息论 / 认知层面**讲得通吗？ | 能用一句话解释"它为什么可能有用"，**且论证不依赖"因为人脑这样"**；引用脑科学时只能引用**可检验的结论与量**，不能拿"像不像脑"当判据 | 不立项 |
| **② 有效性** | 在 **Agent 场景**实测有效吗？ | 有 A/B 数据；指标是 **Agent 能力**（召回质量 / 任务成功率 / token 效率） | **降级为实验特性，不进主线** |
| **③ 正交性** | 与已有机制冲突吗？ | 不与更强机制抢同一份收益；叠加后有增益 | 合并或砍掉 |

### 5.2 四条纪律

1. **禁止以"人脑如此"作为立项理由**——它只能作为**假设来源**
2. **禁止以"像不像脑 / 像人一样"作论证或卖点**——脑科学一律表述为"**借鉴脑科学**"（来源），纪律与替换对照见 [TERM-000 §10](./06-术语与命名规范.md)
3. 每个机制必须**可证伪**：写清"什么结果会让我们放弃它"
4. **没有实测支撑的机制不进主线**（对应新增目标 G6「可验证」）

### 5.3 准入闭环

```
有根据（合理性） → 有效果（实测） → 才进主线
```

补上中间这一环，纲领才闭合。**这正是另一个交叉验证 Agent 提出 G6 时想指出的缺口，我完全认同。**

## 6. 逐机制过筛（用 §5 的标准）

### 6.1 应当被筛掉或降级的（①或②存疑）

| 机制 | ① 合理性 | ② 有效性 | 裁决 |
|---|---|---|---|
| **RIF（检索诱发遗忘）** | ⚠️ 生物学成立 | ❓ **可疑**——"因为检索了 A 所以抑制 B"在 Agent 里没有任务收益，反而可能丢掉关键记忆 | **不实现，或实验开关默认关闭** |
| **模式分离（pattern separation）** | ⚠️ 生物功能是防干扰 | ❓ 向量相似度已部分承担该职能 | **待评测**，不进主线 |
| **交错重放（interleaved replay）** | ⚠️ 生物功能是巩固 | ❓ 等价于"批量整理顺序"，需证明优于顺序整理 | **待评测** |
| **元记忆 / 舌尖现象** | ✅ 讲得通（知道自己不知道） | ❓ 依赖检索质量稳定 | **后续版本**（与交叉验证 Agent 判断一致） |
| **按频率衰减删除** | ❌ 与记忆研究结论相悖（§4.1 问题二：重要性与频率是两个独立维度） | ❌ 会系统性淘汰关键低频记忆 | **移除** |

### 6.2 应当保留的（① ②都容易过）

| 机制 | ① 合理性 | ② 有效性 |
|---|---|---|
| **分级加载（L0/L1/L2）** | ✅ 直接对应注意力预算这一真实稀缺资源 | ✅ 可用 token 效率度量 |
| **巩固与升格（情景→语义）** | ✅ 信息论收益明确：压缩 + 去情境化 | ✅ 可用召回质量度量 |
| **多路检索融合** | ✅ 斯坦福三因子已在公开评测上有效 | ✅ 有 benchmark 支撑 |
| **扩散激活 / 共现关联** | ✅ 共现是真实的统计结构 | ⚠️ 需自测（M4） |
| **可审查 / 可迁移** | ✅ **不依赖任何生物学论证**——本身就是产品需求 | ✅ 可直接验收 |

> **一个反直觉但重要的结论**：P 档三条（分级记忆 / 可治理 / 可迁移）**根本不需要脑科学来辩护**。它们是产品需求，天然过关。**脑科学只是 A 档追加目标的假设来源，既不该拿来给 P 档背书，也不构成机制有效性的论据。**

## 7. 结论与建议

### 7.1 对 P5 的结论

> **"遗忘是一等公民"应修正为"注意力分配是一等公民"。**

| 原命题 | 修正后 |
|---|---|
| 遗忘是一等公民 | **注意力分配是一等公民** |
| 手段：衰减 → 删除 | 手段：**分级 + 排序 + 时态** |
| 目的：模拟人脑 | 目的：**在有限注意力下决定此刻想起什么** |
| 删除是认知机制 | 删除是**治理动作**（合规 / 用户意图） |

### 7.2 对 P4 的结论

> **原则本身对，但要补上"有效性"。**

修正为：**「机制必须既讲得通、又测得出」**——神经科学只提供假设，不提供正确性。对应新增目标 **G6 可验证**。

### 7.3 对设计文档的影响（✅ 已回填）

| 位置 | 改动 | 状态 |
|---|---|---|
| `[LLD-AL2 §5 M3](./layers/AL2-核心层详细设计.md)` | 标题与内容改为「**衰减排序与删除治理**」；移除强度触发删除；`archive` 取消；删除白名单两项 | ✅ |
| `[LLD-AL2 §2.2](./layers/AL2-核心层详细设计.md)` `RecallWeights` | `vitality` 拆为 `recency` + `importance` | ✅ |

| **D-19** | RIF / 模式分离 / 交错重放 / 元记忆 列为**实验特性（默认关闭）** | ✅ **采纳** | 08 纲领 §4.2 |

### 8.1 用户对 D-17 的关键补充

> **除了「记忆冲突被修正时的优化性遗忘」之外，应该只允许用户显式要求；用户显式要求本身也是可审核的要素之一。**

这条补充把白名单**从"合规 / 冲突 / 用户"三项收紧到两项**，并且**把"删除请求"本身提升为审计对象**。

**两个后果**：

1. **合规删除不单列入口**——它本质上是"用户 / 数据主体显式要求"的一种，走第 2 项
2. **"谁要求删的"必须留痕**——`audit(op='forget', actor='user', reason, source, ts)`，且审计**先于删除**落库、不随删除而消失

> **设计含义**：删除不再是系统可以自主决定的事。系统的自主权仅限于"**降权**"（可逆），"**销毁**"的权限交还给使用者——而使用者行使这个权限的过程，本身也被完整记录。
> 这同时满足了 P5（可见即可信）、P6（不静默丢数据）与 INV-8（审计 append-only）。

## 9. 一句话总结

> **我们不是要把 Agent 做得像人脑，而是要让 Agent 记得住、找得到、说得清、带得走。**
> **神经科学只是我们的假设来源之一，不是裁判。真正的裁判是 Agent 在真实任务上的表现。**
