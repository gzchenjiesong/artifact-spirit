## 2. 分层详细设计的文档模板

每份 LLD **必须**包含以下十节（顺序固定，便于横向对照）：

| # | 章节 | 内容要求 |
|---|---|---|
| 1 | **职责与边界** | 本层负责什么 / **明确不负责什么**；与相邻层的分界 |
| 2 | **对外接口** | 本层对其他层暴露的协议与数据结构（签名级） |
| 3 | **内部结构** | 模块划分、关键类/函数、数据流 |
| 4 | **依赖** | 依赖哪些层的哪些**协议**；明确禁止依赖什么 |
| 5 | **关键设计** | 本层最核心的 2–4 个设计点，含取舍理由 |
| 6 | **编码注意事项** | 易错点、踩坑提醒、必须遵守的写法约定 |
| 7 | **错误处理与降级** | 本层涉及的故障点及期望行为（对齐概要设计 §6） |
| 8 | **独立验收标准** | 用 fake 依赖可验证的检查清单（**可勾选**） |
| 9 | **集成验收关注点** | 与其他层联调时的验证点 |
| 10 | **待决策 / 未决项** | 本层尚未拍板的设计点 |

## 3. 分层落地与验收原则

### 3.1 逐层开发

```
AL3 存储层（地基，无业务依赖）
  └─▶ AL4 模型层（无业务依赖，可与 AL3 并行）
        └─▶ AL2 核心层（依赖 AL3/AL4 的协议）
              └─▶ AL5 辅助机制（组合根 runtime/lifecycle.py：装配全部依赖）
                    └─▶ AL1 适配层（最后接线：调起组合根）
```

- **AL3 与 AL4 可并行开发**：二者互不依赖
- **AL2 可在 AL3/AL4 之前用 fake 开发**：协议已定，实现可后置
- **AL1 最后接线**：它**调起**组合根（AL5 的 `runtime/lifecycle.py`）完成装配，
  自己不做装配——所以"最后接线"的是 AL1 的**调用时机**，而不是它持有装配逻辑

### 3.2 独立测试手段（fake 策略）

| 被测层 | 替身 | 说明 |
|---|---|---|
| AL1 | fake 核心层 | 返回固定召回结果，验证契约语义 |
| AL2 | 内存 fake backend + fake model | 纯逻辑，无 I/O |
| AL3 | 临时 SQLite 文件 | 真实 DB，无外部服务 |
| AL4 | 本地 mock HTTP | 不依赖真实网关 |
| AL5 | fake backend + 计数队列 | 验证串行化与溢出策略 |

### 3.3 验收两级

1. **层内验收**：该层全部检查项通过 + 不依赖其他层的真实实现
2. **集成验收**：在真实 Hermes 中端到端跑通 + 故障注入逐条生效

### 3.4 完成定义（Definition of Done）

一层视为"完成"，当且仅当：

- [ ] 十节模板齐全，无 TODO 遗留
- [ ] 独立验收标准全部勾选通过
- [ ] 架构规则（概要设计 §4.2 的 R1–R10）对该层检查通过
- [ ] 本层涉及的降级路径有测试覆盖
- [ ] 与相邻层的接口联调通过
