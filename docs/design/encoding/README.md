## 2. 任务编号与结构

编号规则：`T-{层}-{两位序号}`，如 `T-AL3-05`。**编号一旦分配不再重排**（含"空缺"——参见 `D-07` 的先例），新增任务一律**顺延追加**。

每个任务固定**六段**：

| 段 | 内容 |
|---|---|
| **里程碑** | M0 / M1 / M2 / M3 / M4 / M5 |
| **依赖** | 前置任务编号；`无` 表示可立即开工 |
| **产出** | 具体文件路径与函数/类名 |
| **要求** | 实现要点（含必须遵守的约束） |
| **约束** | 该任务触及的不变量 / 架构规则 / 决策（`INV-x` / `R-x` / `D-xx`），执行时不得绕过 |
| **验收** | 可勾选条目，**必须可机械判定** |

**「验收」怎么写才对**（AL1–AL4 复核反复抓出的一类空洞条目）：

| ❌ 不能这么写 | ✅ 要这么写 |
|---|---|
| "与 X 一致" | `inspect` 白名单断言（**两个方向都比**）、链段 `source` 序列、`request_count` 计数 |
| "输出正确" | "往返后逐字相等"、`set(seen) == {expected}` |
| "不阻塞" | 带超时上界的断言（`p99 < 5ms`） |
| "有覆盖" | 指名用例名，且该用例**删掉被测逻辑就会红** |

> **弱断言制造的是"已覆盖"的错觉**：能通过"把被测逻辑删掉"的断言，等于没断言。
> 追溯矩阵（E7）会自动校验"被引用的用例真实存在"，但**断言强度只能靠人判**——所以每加一条验收，先问：
> **"把这条验收要测的那段代码删掉，它还会红吗？"**

## 3. 通用编码约定

### 3.1 语言与工程

| 项 | 约定 |
|---|---|
| Python | **3.11+**（以 `pyproject.toml` 的 `requires-python = ">=3.11"` 为准） |
| 类型注解 | 全量注解；公开接口必须有 |
| 数据类 | `@dataclass(slots=True)`；不可变用 `frozen=True` |
| 协议 | `typing.Protocol`，不用 ABC 继承（除非确有共享实现） |
| 异常 | 自定义异常族，分类明确（详见各层） |
| 时间 | 一律 ISO8601 字符串，禁止混用时间戳 |
| ID | ULID；格式 `{abbr}_{ulid}` |
| JSON 字段 | `scope` / `aliases` / `before` / `after` 显式 `json.dumps/loads` |
| 注释里的引用 | **引用的编号必须真实存在**（`DES-REV-xxx P?-nn`）——已由 `tests/test_doc_refs.py` 机械校验 |

### 3.2 依赖与环境

| 项 | 约定 |
|---|---|
| 必装依赖 | `httpx`、`sqlite-vec` |
| **禁止引入** | 传染性许可（AGPL/SSPL）或许可不明的依赖、图数据库服务、`openai` SDK、`jsonschema` |
| 密钥 | 只从环境变量读（前缀 `ARTIFACT_SPIRIT_`）；**禁止**写入任何文件或日志 |
| 路径 | 一律基于 `hermes_home`；**禁止**硬编码 `~/.hermes`（INV-9） |

### 3.3 分层依赖（R1–R10，CI 强制）

| # | 规则 |
|---|---|
| R1 | `core/*`、`extract/*` 只能依赖协议（`store/base.py`、`model/base.py`）与共享内核，其余越界 |
| R2 | `store/*` 禁止依赖 `core/*`、`extract/*`、`model/*` |
| R3 | `model/*` 禁止依赖 `core/*`、`store/*`；且禁止 `openai` SDK |
| R4 | **只有 `provider.py`** 可依赖 Hermes 契约；其余位置一律禁止 |
| R5 | `core/*`、`extract/*` 禁止出现 `httpx` / `sqlite3` / `openai` |
| R6 | `__init__.py` 只做 `register()`，零业务逻辑 |
| R7 | 任何位置禁止引入传染性 / 许可不明的依赖 |
| R8 | 只有 `runtime/*` 可创建线程，也只有它可用并发 / 异步原语 |
| R9 | **层内实现模块不可跨层**（`store.sqlite_backend` / `model.resolver` / `model.openai_compat`）——跨层请依赖 `*.base` 协议 |
| R10 | **AL5 不得依赖业务层实现**；唯一例外是组合根 `runtime/lifecycle.py` |

### 3.4 测试约定

| 项 | 约定 |
|---|---|
| 框架 | `pytest` |
| 每个任务 | **必须**附对应验收项的测试；验收项即测试名 |
| 替身 | 各层用其指定的 fake（见 §5），**不得**在上层测试中引入下层真实实现 |
| 断言风格 | 优先断言**行为与不变量**，而非实现细节 |
| 架构测试 | 独立 `tests/test_arch.py`，固化 R1–R10 |

## 6. 完成定义（DoD）

**单个任务**：六段齐全 + 要求实现完毕 + 验收项**全部勾选** + 门禁全绿。

**单层完成**：该层全部任务通过 + 架构规则检查通过 + **降级路径有测试覆盖**。

**里程碑出口**（每一批交付的判据）：

| 里程碑 | 出口条件 |
|---|---|
| **M0** | 契约打通：`initialize` / `is_available` 可用，配置装载与校验可运行 |
| **M1** | 工具面与热路径：`prefetch` / `sync_turn` 非阻塞，工具集可调 |
| **M2** | **MVP**：五类记忆各自完成 + V1 / V2 / V3 三条核心价值有端到端判决 + 量化门槛（LoCoMo ≥ 70、LongMemEval ≥ 75）自测留痕 |
| **M3** | 时态与遗忘治理：双时态可查、三态去重生效、衰减**只影响排序**（不删除）、交叉验证异步限频、**完整包往返导入零新增** |
| **M4** | 关联与进化：扩散激活默认一跳（`hops > 1` 抛 `NotImplementedError`）、进化有审计、核心记忆可干预 |
| **M5** | 可观测与传承：`status` / `audit` / `doctor` / `trace` 齐全、**CLI 全套**、传承导出**在无器灵环境可读懂、且可重建** |

> **M3–M5 的每一批都必须"自身完整可验收并过门禁"后才进入下一批**——不允许"先铺开、再收口"。

## 10. 常见缺陷（来自两轮评审 + AL1–AL5 逐层复核，开工前扫一眼）

| 模式 | 表现 | 出处 |
|---|---|---|
| 静默丢失 | 设计里说的机制，代码里没有，也没说明 | DES-REV-001 |
| 只做一半 | 移除了旧触发条件，没给新判据 | DES-REV-001 |
| 悬空接口 | 上层有入口，下层无对应方法 | DES-REV-001 |
| **热路径违规** | 在 `prefetch` / `sync_turn` 里做 LLM 调用或全量扫描 | DES-REV-001 |
| 定义空洞 | 用了某个权重/阈值，但没定义它怎么算 | DES-REV-001 |
| 往返不幂等 | 导出再导入产生重复 | DES-REV-001 |
| **弱断言（恒真 / 半恒真）** | `... or True`、`or len(set(seen)) == 1`、`isinstance(x, list)`——**删掉被测逻辑照样通过** | DES-REV-004 / 008 |
| **契约副本落后** | LLD 的 §2 接口副本比实现少成员，甚至**虚构不存在的符号**（`StatusReport` / `MaintenanceScheduler`），而上层只按这份文档对契约 | DES-REV-005~008 |
| **静默降级 / 静默兜底** | 未登记的 op / kind / action 落到"默认档"，于是队列"看起来在工作" | DES-REV-003 / 008 |
| **双真相源** | 同一件事有两份投影或两套编号语义（schema 版本、审计编号），迟早错位 | DES-REV-003 / 008 |
| **靠自觉的约束** | 关键正确性写在 docstring 的叮嘱里（"调用方必须…"），而不是让**正确行为成为默认** | DES-REV-008 |
| **注释级悬空引用** | 注释引用了不存在的评审编号 / 用例名 / 规则号——**引用一个不存在的裁判，等于没引用** | DES-REV-007 / 008 |
| **不终止的函数** | 循环的退出条件在边界输入下不可达（`budget == 1` 时"逐字回退"原地打转）→ **挂死宿主** | DES-REV-009 |
| **跨线程写共享状态** | 后台线程直接改调用方可见的状态，或**绕过单写者直接落库** | DES-REV-004 / 008 |
| **断言在收尾后失效** | 断言依赖生命周期对象（线程 id / 连接）的当前值，而它在 `stop()` 后变成 `None` → 用例**退化成恒真** | DES-REV-008 |

> **两条通用判据**（比上表更重要）：
> ① **"用例会红"不等于"用例有效"**——要问"把这条要测的逻辑删掉，它还红吗"；
> ② **"规则报绿"不等于"规则在工作"**——每条约束都要配一个**注入违规的反例用例**。
