# 器灵 / Artifact Spirit — 知识型记忆研究与机制增补

> 文档编号：**DES-RES-004**
> 日期：2026-09-15
> 触发：**五类记忆回答不了"助手自己的知识积累"**——游戏开发助手要收着大量技术资料、学习助手要记着知识点、生活助手攒着旅游攻略与各国注意事项。这类记忆的**来源不是经历而是外部导入**，规模大、时效长、只在需要时被搜到。它既不该按"经历"的方式入库，也不该在平时占用注意力。
> 结论摘要：**知识型记忆不是第六类记忆，而是语义记忆的"外置来源分支"**（`layer=semantic`）；它的三个例外条款是——**不过显著性门、不随时间衰减、默认零注入**；落地形态是**目录卡（catalog card）+ 按需检索 + 片段注入**，即"书在架上不占注意力，目录卡占一点点，正文按需取"。

## 1. 问题界定：什么是"知识型记忆"

### 1.1 与五类记忆的差异不在"内容"，在**来源与生命周期**

| 维度 | 经历型记忆（情景 / 语义 / 程序） | **知识型记忆** |
|---|---|---|
| 来源 | Agent 与宿主的**交互中提炼** | **外部导入**（文档 / 资料 / 攻略 / 教程） |
| 产生方式 | 提取器逐轮抽取、巩固升格 | **批量导入**，一次成百上千条 |
| 规模 | 千~万级 | **万~百万级**（一个技术栈的文档就是几千段） |
| 是否随时间失效 | 是（时态 + 被取代） | **多数不失效**，但**会过时**（版本 / 政策 / 价格） |
| 被用到的触发 | **情境触发**（当前话题像不像它） | **需求驱动**（当前任务**需要**这类知识） |
| 复用性 | 与本次情境强相关 | **跨会话反复复用**（同一个知识点会被问很多次） |
| 典型失败模式 | 记错了、记串了 | **淹没注意力**、**搜不到**、**用过期版本作答** |

> **关键差异**：经历型记忆是"**我经历过什么**"，知识型记忆是"**我备着什么资料**"。

### 1.2 结论：不是第六类记忆，而是语义记忆的**外置来源分支**

| 选项 | 评价 |
|---|---|
| 新增 `layer="knowledge"` | ❌ 会与"五类记忆"这一已经稳定的分类体系冲突（[TERM-000 §5](./06-术语与命名规范.md)），且它承载的是**语义知识**，硬拆成一层会让召回、巩固、迁移全部多一条分支 |
| **复用 `layer="semantic"` + `type="knowledge"` 区分** | ✅ **推荐**：知识型记忆与语义记忆**同构**（去情境化的事实与概念），差异只在**来源与治理条款**——用 `type` / `scope` 表达即可，不动分层 |

**术语建议**（待 [TERM-000](./06-术语与命名规范.md) 收录）：

- **知识型记忆（Knowledge Memory）**：由外部资料导入、以检索为主要唤醒方式的一类语义记忆。
- **目录卡（Catalog Card）**：每条知识记忆上的一条**极短索引描述**（约 15–25 token），用于"不读正文就知道这条讲什么、值不值得展开"。
- **知识通道（Knowledge Channel）**：知识型记忆从导入、编目、检索到注入的完整链路（§3）。

### 1.3 典型形态（决定机制必须支持什么）

| 助手类型 | 积累内容 | 形态 | 时效要求 |
|---|---|---|---|
| 游戏开发助手 | 引擎 API、渲染管线、性能调优经验、踩坑记录 | 长文档 + 片段 + 代码 | **版本敏感**（引擎大版本升级即过期） |
| 学习助手 | 知识点、公式、例题、错题归因 | 短条目 + 层级结构（章 / 节 / 点） | 长期有效 |
| 生活助手 | 旅游攻略、签证政策、当地禁忌、办事流程 | 碎片条目 + 时效（价格 / 政策） | **高度时效** |
| 通用（个人） | 读书笔记、会议纪要沉淀、摘录 | 混合，且**来源常带个人判断** | 与来源绑定 |

> 这四个用例的共同结构：**条目多、平时不用、需要时必须找得到、答案要能指出来源。**

### 1.4 与"不做通用知识管理"的边界（README 既有承诺）

README 明确写了器灵**不做通用知识管理**。这条承诺**不因本文而变**，边界如下：

| 器灵**做** | 器灵**不做** |
|---|---|
| 把外部资料当作**一类记忆**保存、检索、注入 | 知识编辑 / 双链笔记 / 协作与权限 |
| 复用同一套**审计、治理、迁移**（P2/P3 一视同仁） | 组织级知识库 / 文档解析流水线产品化 |
| 提供**目录卡 + 检索**，让宿主按需取用 | 做 RAG 框架 / 做向量数据库（[ADR-002](./02-底层存储选型.md)） |

> 一句话：**知识型记忆是"器灵帮宿主记住的资料索引与片段"，不是"器灵做一个知识管理软件"。**

## 2. 研究依据（五支）

引用格式同 DES-RES-003：结论 + 强度（A/B/C）+ 对设计的直接含义。**这一节是本文的主体**——因为它回答的是"海量外部资料该怎么组织才能被找到"。

### 2.1 图书馆学与知识组织：**描述与内容分离**

| # | 结论 | 强度 | 直接含义 |
|---|---|---|---|
| 1 | **目录（catalog）与藏书（collection）自古就是两件事**：读者先查目录卡，再去取书 | A | **目录卡进上下文，正文留库里**——这是本设计的主结构（§3 K2） |
| 2 | **元数据描述独立于内容**：Dublin Core（15 元素）、MARC 都是"先描述、再检索" | A | 每条知识记忆需要**可检索的描述字段**，而不是只有正文 |
| 3 | **分面分类**（Ranganathan 1933 冒号分类，PMEST）优于单一层级 | B | 一条知识**同时属于多个面**（主题 / 来源 / 时效 / 适用范围）→ 多标签，而非一棵树（也解释了为什么"目录树"不该是主结构） |
| 4 | **受控词表 / 主题标目**（LCSH）用规范化词表缓解同义异形 | B | 标签与实体需要**归一化**（项目已有 `entities.aliases`，可直接承接） |
| 5 | **FRBR（IFLA 1998）**：把"作品 / 表达 / 载体"分层，因为同一作品有多种版本与载体 | B | 同一知识的多来源多版本要能**共存并指向彼此**（`superseded_by` / 版本字段） |
| 6 | **最小努力原则**（Zipf 1949；信息行为综述 Case & Given 2016）：人倾向最省力的信息路径 | B | 检索必须**一次命中**；要求用户"多轮下钻"的目录树是反人性的设计 |

> **这支文献的最大贡献**：它给出了"**书在架上不占注意力**"的完整先例——人类图书馆用了几百年解决"藏书量爆炸 + 读者注意力有限"，答案不是压缩藏书，而是**编目**。

### 2.2 信息检索：召回靠多路，注意力靠"信息气味"

| # | 结论 | 强度 | 直接含义 |
|---|---|---|---|
| 1 | **Cranfield 范式**（Cleverdon 1962/1966）：召回率 / 精确率可测量、可权衡 | A | 知识型记忆的验收标尺（§6） |
| 2 | **倒排索引 + BM25**（Manning et al. 2008；Robertson & Zaragoza 2009）：术语精确匹配是不可替代的一路 | A | 沿用 `keyword_search`（FTS5/BM25）；**专有名词、API 名、地名**只能靠它 |
| 3 | **稀疏 + 稠密互补**；**RRF（Cormack et al. 2009）**用排名融合，免去分数量纲归一化 | A | 现设计是"归一化后加权求和"（AL2 §5 M5）；RRF 是**可选的、更省心的融合备选**，值得在 M5 做 A/B |
| 4 | **两阶段检索 + rerank**（Nogueira & Cho 2019）：先粗召回再精排 | A | 器灵已明确放弃 rerank（热路径成本）→ 补偿手段就是**目录卡粗筛 + 小候选集** |
| 5 | **信息觅食理论**（Pirolli & Card 1999）：**信息气味**决定是否继续投入检索 | A | **目录卡 = 信息气味**。没有它，模型只能"盲翻正文"或干脆不搜——这是 K2 的理论根据 |
| 6 | **ASK 假说 / 问题协商**（Belkin 1980；Taylor 1968）：信息需求起初是模糊的，靠检索过程逐步明确 | B | 支持"**先给浅层、再按需展开**"，也支持"**缺口可见**"（元认知） |

### 2.3 个人知识管理（笔记 / 碎片信息）

| # | 结论 | 强度 | 直接含义 |
|---|---|---|---|
| 1 | **摘录 + 归类**是知识积累的原始形态（Commonplace book 传统） | B | 导入流程要允许"**先收录、后整理**"，不能要求用户先建好体系 |
| 2 | **Zettelkasten**（Luhmann；Ahrens 2017）：原子化 + 唯一标识 + 主动建链 | B | 与既有 `relations` 边、A-MEM 一脉（[DES-RES-001 §2.3](./03-记忆质量调研.md)）——知识条目也吃这套 |
| 3 | **渐进式摘要**（Forte）：只对"要用的"材料逐层压缩 | C | 对应 K3 层级（目录卡 → 章节摘要 → 段落），**压缩深度按需投入** |
| 4 | **PIM 研究**（Jones & Teevan 2007；Bergman & Whittaker 2016）：收藏与使用是两回事，**大量条目长期零命中是常态** | A | **零命中不是删除理由**（与 [D-16/D-23](./00-方案设计.md) 一致），只降权或提示整理 |
| 5 | **收藏悖论**（collector's fallacy / read-later 研究）：只收藏不消化 | B | 导入需要**用途与覆盖面判据**；批量导入不能变成"库存膨胀" |

### 2.4 认知侧：交互记忆与认知卸载

| # | 结论 | 强度 | 直接含义 |
|---|---|---|---|
| 1 | **交互记忆**（Wegner 1985/1987）：个体/团队靠"**知道在哪里、谁知道**"扩展可用记忆，而不必内化内容 | B | **Agent 应保存"有这份资料、它讲什么、在哪"，而不是把全文内化成常驻上下文**——这是知识通道的第一原则 |
| 2 | **"Google 效应"**（Sparrow et al. 2011）：知道能查到，反而降低对内容本身的记忆 | B | 双刃剑：可达性提升能力，但**一旦检索不可靠就等于真丢** → 检索质量是硬指标，不能只有"存了" |
| 3 | **认知卸载**（Risko & Gilbert 2016） | A | 卸载成立的前提是"**能可靠取回**"；否则不如不卸载 |
| 4 | **知晓感（FOK）** | C | 缺口可见："关于 X 我**没有**积累"必须能说出来（与 DES-RES-003 §6.4 S-4 同一件事） |

### 2.5 检索增强（LLM 侧）

| # | 结论 | 强度 | 直接含义 |
|---|---|---|---|
| 1 | **RAG**（Lewis et al. 2020）：参数记忆 + 非参数检索，把**片段**放进上下文 | A | 器灵同路，但比典型 RAG 多两样：**分级 + 治理**（审计 / 迁移 / 删除白名单） |
| 2 | 检索单位应是**段落**而非整篇（Karpukhin et al. 2020） | A | 命中后注入**片段 + 出处**，禁止整文注入（§3 K4） |
| 3 | **递归摘要树**（RAPTOR；Sarthi et al. 2024）在长文档上有效 | A | 目录卡 → 章节摘要 → 段落的三级，是**已被验证**的结构，不是自创 |
| 4 | **HyDE**（Gao et al. 2022）等查询改写可提升短查询召回 | B | 可作为 K4 的可选增强（**注意热路径成本**，沿用 M5 的"放弃意图分析"立场需一并评估） |
| 5 | **长上下文中间遗忘**（Liu et al. 2023；见 DES-RES-003 §2.3） | A | 注入要**少而准**，位置亦有影响 |
| 6 | **时效与知识冲突**：时间感知模型（Dhingra et al. 2022；Lazaridou et al. 2021） | B | "语义相似"救不了过期知识 → **必须有时效与版本信号**（§3 K6） |
| 7 | **近重复检测**（Broder 1997 shingling/MinHash；Charikar 2002 SimHash） | A | 同一资料的重复导入要合并；项目已有精确指纹（`content_hash`，D-21），近重复是增量能力 |

### 2.6 研究 → 设计：一句话对应表

| 研究给的 | 落到哪 |
|---|---|
| 目录与藏书分离（§2.1-1） | **目录卡进上下文、正文留库**（K2/K4） |
| 分面分类（§2.1-3） | 多标签而非目录树（K2） |
| 信息气味（§2.2-5） | 目录卡**必须**短且可判断（K2/K5） |
| 段落级检索 + 递归摘要（§2.5-2/3） | 三级层级 + 片段注入（K3/K4） |
| 交互记忆（§2.4-1） | **保存"在哪里"，不内化全文**（总原则） |
| 时效与版本（§2.5-6） | K6：不衰减，只时效 |
| PIM：零命中是常态（§2.3-4） | K7：不删，只降权 / 提示整理 |

## 3. 机制设计：知识通道（Knowledge Channel）

> 一句话：**书在架上不动，目录卡占一点点，正文按需取，取到就指出出处。**
> 下文 K1–K7 是七条设计决策，每条都配"依据 + 落点 + 判据"。

### 3.1 K1 入口：**批量导入，不过显著性门**

| 项 | 内容 |
|---|---|
| 依据 | M1 显著性门是"**经历的门**"（判断一段交互值不值得记）；知识是**外部资料**，没有"值不值得经历"的问题（§2.3-5 收藏悖论：需要的是**用途与覆盖面**判据） |
| 落点 | 知识走**独立入口**（`type="knowledge"` + 导入工具/API），**不经过** `sensory` 显著性打分；导入时记 `source`（来源标识）与覆盖面标签 |
| 判据 | 导入吞吐（条/秒）与**上线后命中率**；若某批知识 90 天零命中 → 提示宿主"这批没被用过"（K7），**而不是**自动删 |

### 3.2 K2 目录卡：**不读正文就知道讲什么**

| 项 | 内容 |
|---|---|
| 依据 | 目录与藏书分离（§2.1-1）+ 信息气味（§2.2-5） |
| 形态 | 复用**已有字段** `MemoryRecord.abstract` 作目录卡（L0 摘要），预算沿用仓库既有常量 **24 token**（`REMEMBER_ABSTRACT_BUDGET` / `OVERVIEW_PIECE_BUDGET`） |
| 要求 | 目录卡必须回答三件事：**讲什么 / 属于哪个面 / 有多新**——即"主题 + 分面标签 + 时效"可判 |
| 分面 | 用 `scope`（global / project / session）+ `entities`（主题与专有名词）+ 时效字段表达，**不做目录树**（§2.1-3 分面分类；AL2 M5 已放弃目录递归，理由见 §4） |
| 去重 | 精确去重沿用 `content_hash`（D-21 / INV-14）；**近重复**（同一份资料换个格式再导入）是增量能力（§2.5-7），MVP 可先只告警不合并 |

### 3.3 K3 层级：**目录卡 → 章节摘要 → 段落**（复用 L 体系，不新增编号）

| 知识视角 | 映射 | 体量 | 生成时机 |
|---|---|---|---|
| **目录卡**（这条讲什么） | `L0`（`abstract`） | ~24 token | 导入后异步 |
| **章节 / 主题摘要**（这类知识大概有什么） | `L1`（`overviews` 表，scope 维度） | ~2k token | 冷路径预生成 + 缓存（N-P0-2：热路径不生成） |
| **段落原文 + 出处**（准确表述） | `L2`（`content` + `relations` + 来源） | 按需 | 实时组装，**只读** |

> **与经历型记忆的唯一区别**：知识型记忆的 `L1` 按 **知识主题/来源** 组织（如"引擎渲染管线"），而不是按会话/实体；`L2` 注入的默认单位是**段落片段 + 出处**，不是原文全篇（§2.5-2）。语义与编号**完全复用** `L0/L1/L2`——这是 DES-RES-003 §2 的分级在知识场景的直接应用，不需要新体系。

### 3.4 K4 唤醒：**两条通路，主力是"显式检索"**

| 通路 | 机制 | 何时用 |
|---|---|---|
| ① **自动注入**（被动） | 与经历型记忆共用 M5 六因子召回，但知识型条目**默认只以目录卡候选出现**（且总量设上限） | 当前话题明显与某批知识相关 |
| ② **显式检索**（主动） | 既有工具 `spirit_recall`（可选 `layers` / `top_k` / `token_budget`）→ 命中后 `spirit_expand(L0/L1/L2)` 逐级展开 | **模型自己判断"我需要查资料"**——这是知识型记忆的主要唤醒方式（§2.4-1 交互记忆：知道有，才去取） |

**检索实现**：沿用双路并行（`vector_search` 语义 + `keyword_search` BM25）→ 六因子融合（AL2 §5 M5）。**不引入 rerank、不引入意图分析**（热路径成本，AL2 M5 已裁决），因此"目录卡粗筛 + 小候选集"就是精排的替代品。

### 3.5 K5 注意力护栏：**知识不常驻**

| 护栏 | 取值 | 依据 |
|---|---|---|
| 目录卡长度 | ≤ 24 token/条 | §2.1-1（目录卡必须极短才有意义） |
| 自动注入的知识条目数 | ≤ 3 条/轮（且仅目录卡级） | 注意力预算（DES-RES-003 §2） |
| 知识注入预算占比 | ≤ 本轮记忆注入预算的 **1/3**（其余留给经历型记忆与工作记忆） | §2.4-3（卸载必须留出主任务的余量）；与工作记忆 5 组块（M6）同源 |
| 单次片段注入 | ≤ 400 token/片段；**禁止整文注入** | §2.5-2/5（段落级检索 + 中间遗忘） |
| 常驻系统提示 | 知识型记忆**不进** `system_prompt_block` 常驻区 | K5 核心：只在需要时进入上下文 |

> **这条是"不压注意力"的真正落点**：知识型记忆与经历型记忆**共用预算池但优先级更低**——预算不足时，先舍知识（它不是"我是谁"的一部分）。

### 3.6 K6 生命周期：**不随时间衰减，只随版本过期**

| 项 | 内容 |
|---|---|
| 依据 | M3 的"时间衰减"建模的是**经历的可及性**（久不想就难想起）；知识**不因不被访问而变得不真**（§2.5-6）→ **知识型记忆豁免时间衰减** |
| 取代品 | `valid_from` / `valid_to`（双时态，已有字段）+ `superseded_by`（已有字段）+ 来源权威性（`confidence` 兼任） |
| 语义 | 过期知识**不是"淡忘"，是"过时"**：仍可召回，但必须**同时带出"这是旧版本"**或指向 `superseded_by` |
| 判据 | **陈旧误用率**：因使用过期知识导致的错误回答比例（目标 0，允许"标注后仍可用"） |

### 3.7 K7 治理：**缺口可见、出处可溯、未用不删**

| 项 | 内容 |
|---|---|
| 依据 | 交互记忆与知晓感（§2.4-1/4）+ PIM"零命中是常态"（§2.3-4） |
| 缺口可见 | 检索空结果时返回显式提示（"关于 X 我没有积累"），而不是静默空——与 DES-RES-003 §6.4 S-4 同一机制 |
| 出处可溯 | 命中即带 `source`；注入片段必须可被 `spirit_trace` 追溯到来源与版本 |
| 未用不删 | 长期零命中的知识条目**只降权 / 提示整理**，物理删除仍只走两个白名单入口（D-17） |
| 库存体检 | 定期输出"覆盖面报告"：哪类知识只有 0–2 条（缺口）、哪类重复度高（§2.5-7） |

### 3.8 K1–K7 汇总

| # | 决策 | 依据 | 一句话判据 |
|---|---|---|---|
| K1 | 批量导入、不过显著性门 | §2.3-4/5 | 命中率而非"入库量" |
| K2 | 目录卡（24 token）+ 分面标签 | §2.1-1/3、§2.2-5 | 只看目录卡就能判断相关性 |
| K3 | 复用 L0/L1/L2 做三级 | §2.5-3 | 展开不丢信息、逐级可停 |
| K4 | 自动注入（弱）+ 显式检索（主） | §2.4-1 | 需要时必找得到 |
| K5 | 知识不常驻、预算 ≤1/3 | §2.4-3、DES-RES-003 §2 | 知识注入 token 上界 |
| K6 | 不衰减、只时效 | §2.5-6 | 陈旧误用率 |
| K7 | 缺口可见、出处可溯、未用不删 | §2.4-1/4、§2.3-4 | 空召回有解释；零命中不消失 |

## 4. 与现有机制的接口与冲突裁决

| 现有机制 | 关系 | 裁决 |
|---|---|---|
| **M1 显著性** | 知识**不过**这道门 | 门是"经历的门"。知识改走覆盖面/来源判据（K1）——**不是放松门槛，是换一把尺** |
| **M3 衰减** | 知识**豁免**时间衰减 | 保留 M3 给经历型记忆；知识用**时效与版本**（K6）。两者都以"排序信号"方式生效，不涉及删除 |
| **M5 六因子融合** | **共用**，但知识因子权重不同 | 知识型记忆的 `recency`（时间邻近）应替换为"**时效有效性**"（`valid_to` 之后的条目降权），`importance` 由来源权威性承担 |
| **M5 目录递归下钻（已放弃）** | **不冲突** | 放弃的是**以目录树为存储/检索主结构**（INV-1 结构化真相源）；K2 的"目录卡"是**每条记录上的一个短字段**，不是目录树。→ AL2 §5 M5 表下补一句澄清（本次已回填） |
| **M9 分级加载（P1）** | **直接复用** | 知识是 L0/L1/L2 的第二个使用者；唯一新增是"默认零常驻注入"（K5） |
| **M6 工作记忆 5 组块** | **共享同一预算观** | 知识注入与工作记忆同池竞争，故设 1/3 上限 |
| **INV-1 真相唯一** | **遵守** | 目录卡与 L1 都是缓存/派生；真相仍是 `memories.content`（含 `abstract`） |
| **D-16 / D-17 / D-23 遗忘纪律** | **遵守** | 知识零命中不删除，只降权（K7） |
| **README"不做通用知识管理"** | **不冲突** | 见 §1.4 边界表：器灵提供记忆通道，不做知识管理软件 |
| **P2 记忆可审查（M11）** | **沿用** | 知识的入库、检索、注入同样进 `audit`；`spirit_review` 可按 `layer` 查看 |

## 5. 落地影响：**复用为主，最小改动**

### 5.1 现有结构已能表达的部分（无需改 schema）

| 需要的东西 | 现有字段 / 能力 |
|---|---|
| 归属"这是知识" | `MemoryRecord.type = "knowledge"`（`type: str`，已存在） |
| 分面 / 适用范围 | `scope = {"type": "global|project|session", "id": ...}` |
| 主题与专有名词 | `entities` + `relations(rel_type='mentions')` |
| 时效与版本 | `valid_from` / `valid_to` / `superseded_by`（双时态已就绪） |
| 来源与权威 | `source_session` / `source_turn` / `confidence`（导入时写入来源标识） |
| 精确去重 | `content_hash`（D-21 / INV-14）+ `find_by_hash` |
| 目录卡 | `abstract`（L0 摘要，异步生成） |
| 主题级概览 | `overviews` 表（`L1`，带 `stale` 标记） |
| 逐级展开 | `spirit_expand`（L0/L1/L2） |
| 显式检索 | `spirit_recall`（`query` / `layers` / `top_k` / `token_budget`） |
| 审计与治理 | `audit`（append-only）+ `spirit_trace` / `spirit_review` |

> **结论：知识通道不需要新的层、新的表、新的存储后端**——它是既有结构的**一种用法**。

### 5.2 需要补的三处（都很小，且各自都有先例）

| # | 缺口 | 为什么非补不可 | 建议 |
|---|---|---|---|
| **G-a** | 检索原语无法按 `type` 过滤 | `vector_search` / `keyword_search` 只有 `layer` 参数，而知识与非知识**同在 `semantic` 层** → 无法"只搜知识"或"召回时排除知识"，K4 的显式检索无法定向 | 给两个检索原语加 `types` 参数（`query()` **已有** `types` 先例，属对齐而非发明）；`MemoryBackend` 是稳定接口，须按 R1 走一次显式接口变更 |
| **G-b** | 无批量导入入口 | 工具面只有单条 `spirit_remember`（`confidence` 默认 0.9、无来源字段）→ 几千条资料无法入库 | 新增 **`spirit_ingest`**（工具 + CLI `aspirit ingest`；命名见 [TERM-000 §11.4 ⑦](./06-术语与命名规范.md)）：**幂等 + 只存不编 + 记来源**，批量分片写，不进热路径。⚠️ **不要**用 `spirit_import`——该名已被 [LLD-AL1 §2.3](./layers/AL1-适配层详细设计.md) 的**传承重建**占用 |
| **G-c** | `L1` 概览按"会话 / 实体 / 项目"组织 | 知识需要按**主题 / 来源**组织（"引擎渲染管线讲了什么"）。**核实结果：`scope_kind="topic"` 已实现**（`schema.sql` 注释与 `progressive._scope_records` 均有分支），只缺 **`source`（按来源）** 一档 | 起步直接用 `topic`（**零改动**）；`source` 一档若确需，属 `scope_kind` 取值扩展，仍复用 `overviews` 表与 `stale` 机制 |

> 另外两项**候选配置**：知识注入预算上限（K5 的 1/3）与单片段上限（400 token）需要一个配置承载地（AL5 参数体系），**不要写死在代码里**。

### 5.3 阶段建议（不进 MVP）

| 阶段 | 做什么 | 理由 |
|---|---|---|
| **MVP** | **不做** | MVP 的目标是"五类记忆 + 分级加载跑通"；知识通道是**增量场景**，不阻塞核心 |
| **M3** | G-a（`types` 过滤）+ G-b（导入入口）+ K1/K4 显式检索 | 最小可用闭环：**能导入、能搜到、不常驻** |
| **M4** | 目录卡质量优化、近重复合并（MinHash/SimHash）、缺口与覆盖面报告（K7）、K5 预算护栏调优 | 需要 M3 的真实使用数据才能定参数 |

## 6. Agent 侧判据（验收）

### 6.1 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **命中率** | 需要该知识时，它能出现在候选 / 被显式检索到 | ↑（主指标） |
| **注意力占用** | 知识注入 token / 该轮记忆注入总 token | **≤ 1/3**，且无知识时 ≈ 0 |
| **目录卡可判性** | 只看目录卡就能判断"要不要展开"的抽样准确率 | ↑（人工抽样即可） |
| **陈旧误用率** | 因使用已过期知识导致的错误回答占比 | → 0（或必须带"这是旧版本"标注） |
| **缺口可见性** | 无积累时给出显式提示的比例 | 100% |
| **来源可溯性** | 注入片段能追到 `source` 与版本的比例 | 100% |

### 6.2 对照实验（判定 K2/K4 是否成立）

| 组 | 注入方式 |
|---|---|
| **A（基线）** | 检索命中即把**整篇原文**塞进上下文 |
| **B（本设计）** | 目录卡粗筛 → 命中注入**段落片段 + 出处**，需要时 `spirit_expand` 展开 |

**同时看**：任务回答质量（不降）+ 注入 token（显著降）。只看其中一边不算通过（与 DES-RES-003 §6.2 同规矩）。

### 6.3 放弃条件

| 若…… | 则…… |
|---|---|
| B 组质量不优于 A，而 token 也没降 | K2/K4 不成立 → 退回"直接检索 + 片段注入"，不做目录卡层 |
| 显式检索使用率极低（模型从不主动查） | 说明唤醒通路设计错了 → 改为更积极的自动候选注入（K4 ①），或提高工具的可见性 |
| 知识注入预算 1/3 仍显著挤占任务表现 | 下调上限直至出现质量拐点，或改为"仅在模型显式要求时注入" |
| 时效字段无法可靠获得（导入时无从判断） | K6 降级为"**来源时间 + 提示不确定性**"，并如实告知 |

## 7. 与业界 RAG 管线的分野

| 能力 | 典型 RAG 管线 | 器灵（知识通道） |
|---|---|---|
| 文档解析 / 分块流水线 | 核心产品能力（产品化） | **不做**：由宿主或导入方提供结构化条目（§1.4） |
| 存储 | 向量库 / 检索服务 | **复用**同一 SQLite 真相源（ADR-002，零服务） |
| 检索 | 向量 / 混合 + rerank | 复用 M5 六因子（**无 rerank**，用目录卡补偿） |
| 记忆治理 | 通常没有 | **有**：审计、可审查、可恢复、白名单删除（P2 / D-17） |
| 分级 | 少见（多为"取 Top-K 段落"） | **有**：L0/L1/L2 逐级展开（P1） |
| 时效 | 少见 | **有**：双时态 + `superseded_by`（K6） |
| 与其它记忆的关系 | 独立系统 | **同一套记忆体系的一员**，共享预算与调度 |

> 一句话：**器灵不是 RAG 框架，而是"把外部知识也当记忆治"的记忆系统。**

## 10. 一句话总结

> **知识型记忆不是"第六类记忆"，而是语义记忆的一个外部来源分支**；它的全部特殊性就三条——**不过显著性门（不是因为经历过）、不随时间衰减（只是因为会过时）、不常驻上下文（只在被搜到的那一刻占注意力）**。图书馆学早就替我们把这套问题解过了：**藏书可以无限膨胀，注意力靠"编目"来省**——器灵的对应物就是**目录卡 + 按需检索 + 片段注入 + 出处可溯**。
